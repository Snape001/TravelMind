# 报告地图与路线预览

报告正文内的「目的地地图与游览规划」和陆知行的工作台预览共用路线组件。陆知行完成路线分工后，入口显示在现有三栏的专家公会。预览以弹窗展示，保留原有工作台和 Research Browser。

报告按版本调用 `GET /api/v1/tasks/{task_id}/reports/{report_id}/map-data`，前端类型由实际 FastAPI OpenAPI 生成。陆知行完成分工后，工作台从 `/tasks/{task_id}/routes` 读取先行的已选路线。报告通过审核后，工作台预览使用报告版本的完整快照。 [地图查询契约](phase-4-travel-planning.md#地图查询)

景点按每日行程中的首次出现顺序编号，未安排进每日行程的 POI 在「全部景点」视图可看。景点详情展示地点类别、地址、建议到访时间和停留分钟。报告正文中唯一匹配的官方名称可选择对应 Marker，需要时切换到景点所在日。Marker 详情列出包含其名称的章节。

「按计划」展示已选路线。切换交通方式时，可在当前路段的同方式备选路线间切换，并查看距离、预计耗时、高德查询时间和已关联的路线证据。每个 `segments[].path` 独立交给一条 Polyline，公交与轨道交通用黛蓝描绘。公交换乘详情显示供应商线路和上下车站名。缺少某段几何时仍可看该段已知的站点和通勤数据。仅当该路线没有分段记录时，使用兼容的 `TravelRoute.polyline`。

地图在有路线和有效坐标时加载高德 Web JS API 2.0。公开 JS Key 由已登录会话通过 `/_AMapService/config` 获取，现有同源代理负责 JS 安全配置。路线和 POI 数据由应用后端提供。地图 SDK 加载失败时保留景点和通勤数据，路线为空或读取失败时保留报告正文。

后端 `partial` 状态显示可展开的数据缺口，已有点位与分段仍可查看。历史报告的 `unavailable` 显示空状态。路线或 SDK 加载失败时可重试，报告正文保留。

联调使用 `1b394f2` 的 FastAPI、默认 Worker、隔离 PostgreSQL 17 和生产 Next.js。实际提交泉州大开元寺问卷，Worker 通过真实高德和 DeepSeek 发布报告。正式 MapData 接口返回 2 天、7 个真实 POI、7 个方案、2 条已选路线和 73 个几何分段。另一账户访问任务路线与报告地图均返回 404。Chrome 校验了多日切换、站点、停留时间、备选路线、路线证据、正文双向联动及三栏预览，并比对了当前公交方案的 4 条 Polyline 和后端原始分段坐标。模拟地图请求 HTTP 503 后，正文仍可读，重试重新请求正式接口。浏览器请求检查未发现 Web 服务 POI 或路线调用及 JS 安全密钥参数。
