# 报告地图与路线预览

报告正文内的「目的地地图与游览规划」和陆知行的工作台预览共用路线组件。陆知行完成路线分工后，入口显示在现有三栏的专家公会。预览以弹窗展示，保留原有工作台和 Research Browser。

前端依据冻结的 `GET /api/v1/tasks/{task_id}/routes` 和 `TravelRoutesRead` 读取任务路线。景点按照后端返回路线中首次出现的顺序编号，以高德 POI ID 保持稳定。每条 `TravelRoute.polyline` 独立绘制，缺少几何时保留高德返回的距离与预计通勤时间。报告中唯一匹配的官方景点名称可定位 Marker，Marker 的详情列出包含该名称的报告章节。

地图在有路线和有效坐标时加载高德 Web JS API 2.0。公开 JS Key 由已登录会话通过 `/_AMapService/config` 获取，现有同源代理负责 JS 安全配置。路线和 POI 数据由应用后端提供。地图 SDK 加载失败时保留景点和通勤数据，路线为空或读取失败时保留报告正文。

当前仓库的 FastAPI OpenAPI 只包含报告正文接口，Phase 4 的任务路线接口尚未注册。当前冻结路线结构提供每条路线的一条可空折线。报告专属 `MapData`、日期分组、建议停留时间、公交分段及明确的 POI 与章节引用需要后端接口提供。后续联调应使用这些字段替换对应的降级展示。 [现有路线契约](phase-4-contract.md#目的地与路线)

验收使用独立 FastAPI、PostgreSQL 和生产 Next.js。临时读接口返回 A、B 线适配器实际从高德取得并经 `TravelRoutesRead` 校验的泉州路线。Chrome 验证了三个编号景点、两条步行折线、公交缺几何、驾车切换、正文双向联动、工作台预览及故障后重试。浏览器请求检查未发现 Web 服务 POI 或路线调用及 JS 安全密钥参数。
